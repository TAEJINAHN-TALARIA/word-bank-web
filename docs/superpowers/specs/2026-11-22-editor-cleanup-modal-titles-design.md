# 마스터 편집 화면 개선 ① — 문단 정리 모달 · 제목 편집 · 대화 · 고정 배치 (설계)

## 왜

편집자(사용자)의 작업 순서는 ① 제미나이가 만든 원본 확인 → ② Claude의 도움으로 문단 구성·대사 나누기를 **전체 장에서 한 번에** 실행 → ③ 장별 편집이다. 지금 화면은 문단 구성 제안과 대사 나누기가 장마다 따로 있는 두 패널이고, 소설 제목은 읽기 전용이며, 대화창과 챕터 목록은 스크롤하면 화면 밖으로 사라진다. 한국어 마스터가 잘 되어 있으면 뒤 단계가 거의 필요 없다는 방향이므로, 편집 화면이 그 작업의 중심이 되게 한다.

(②단계, 곧 Layer 6 마스터 품질 점검을 편집 창으로 가져오고 승인된 마스터의 마스터 게이트를 "기록만, 막지 않음"으로 바꾸는 일은 이번 범위가 아니다. 사용자가 방향을 정했고 별도 프로젝트로 이어서 한다.)

## 목표 / 비목표

- 목표 1: `문단 정리` 모달 하나에서 전 장에 대해 (a) 대사 나누기(방식 선택) → (b) Claude 문단 구성 제안(장마다 순서대로) → (c) 장별 검토 → (d) 한 번에 적용.
- 목표 2: 소설 제목과 장 제목을 검토 모드에서 편집하고 자동 저장한다. 소설 제목은 `layer1.output.title`에 저장한다.
- 목표 3: 오른쪽 대화창에서 소설 제목·장 제목을 놓고 Claude와 의논한다(제안만, 직접 고치지 않음).
- 목표 4: `lg` 이상에서 왼쪽 챕터 목록과 오른쪽 대화창을 스크롤해도 화면에 고정한다.
- 비목표: 게시된 소설(`published` 모드)의 제목·구조 편집(게시본은 문단 표현 수정만 허용), Layer 6 점검 이식, 제목 후보 목록(`titleCandidates`)을 대화에 싣는 것, 모든 장 일괄 "확인 완료".
- 안티 목표: 승인 뒤의 소설 제목 변경(저장 함수가 검토 대기 상태만 허용), 제목 저장이 조용히 무시되는 것(함수 배포 전 웹이 먼저 나가는 경우).

## 접근 (사용자가 방향 승인: 2026-11-22)

- **문단 정리**: 모달 하나, 한 번에 전 장. 대안으로 "장 단위 패널 유지"는 사용자의 작업 순서(전체 범위 실행)에 맞지 않아 제외. 한 번의 호출에 전 장을 보내는 방식은 응답이 너무 길어져 제외하고, 장마다 순서대로 호출(진행 표시·중단)한다.
- **소설 제목 저장**: story-generator `adminSaveMasterReview`가 선택 필드 `title`을 받아 `layer1.output.title`을 갱신한다. 한국어 게시 제목·삽화 프롬프트·번역 제목이 모두 이 값을 읽으므로 한 곳을 바꾸면 따라간다. 웹이 Admin SDK로 직접 쓰는 대안은 상태 검증을 우회하므로 제외.
- **고정 배치**: 두 열을 `lg:sticky`로 두고 화면 높이 안에서 각자 스크롤.

## 설계

### 1. 소설 제목 저장 (story-generator + 웹)

- `validateMasterReviewSave`에 `title`(선택) 검증을 더한다: 있으면 문자열, 앞뒤 공백을 뺀 길이 1~120. 없으면 변경 없음. 상태 검증(검토 대기만)은 그대로라 승인 뒤에는 거절된다.
- `saveMasterReviewEdits(sessionId, chapters, confirmedChapters, title?)`가 `title`이 있으면 `layerOutputs/layer1`의 `output.title`을 갱신한다(`titleCandidates`는 그대로).
- `adminSaveMasterReview`는 성공 응답에 저장된 `title`을 함께 돌려준다(`{ success: true, title }`, 보내지 않았으면 생략).
- 웹 `saveMasterReview(sessionId, edits, confirmedChapters, title?)`와 `saveMasterReviewAction`이 `title`을 옵션으로 받는다. **`title`을 보냈는데 응답에 같은 `title`이 없으면 오류**("서버가 제목 저장을 지원하지 않아요 — 함수 배포를 확인해 주세요")로 돌려, 함수가 배포되기 전에 웹이 먼저 나가도 저장된 것처럼 보이지 않게 한다. 배포 순서는 함수 먼저, 웹 나중.

### 2. 제목 편집 화면 (검토 모드)

- 머리줄의 제목 `<h1>`을 입력창으로 바꾼다(검토 모드). 게시본 모드는 읽기 전용 그대로.
- `MasterEditor`에 `novelTitle`/`savedTitle` 상태를 더한다. 제목이 저장본과 다르면 `dirty`이고, 자동 저장은 바뀐 제목만 `title`로 보낸다. 제목이 비면 자동 저장은 "건너뜀"(`제목이 비어 있어요`)으로 처리하고 서버에는 보내지 않는다.
- 원고 내려받기·전체 읽기의 제목은 편집 중인 제목을 쓴다.
- 장 제목 입력은 이미 있다(자동 저장 포함). 변경 없음.

### 3. 대화에서 제목 의논

- 대화 요청에 편집 중인 소설 제목을 `title`(선택, 최대 120자)로 실어 보내고, 서버는 그 값을 `buildStoryContext`의 `제목:` 줄에 쓴다(없으면 저장된 제목). 장 제목은 `chapters`에 이미 들어 있어 Claude가 본다.
- `ChatFocus`에 제목 대상을 더한다: `{ novelTitle: true }`, `{ chapterNumber, chapterTitle: true }`. `focusLine`은 `[지금 보는 곳: 소설 제목]`, `[지금 보는 곳: N장 제목]`을 만든다(`stripFocus`는 그대로 동작).
- 대화창 머리에 대상 선택 칩 `문단 | 이 장 제목 | 소설 제목`을 둔다(편집 보기에서만, 기본은 문단). 칩이 `ChatFocus`를 정하므로 입력창 포커스 같은 암묵적 추정은 쓰지 않는다. 전체 읽기 화면은 칩 없이 지금처럼 전체 원고.
- 대화 시스템 프롬프트에 한 줄을 더한다: 제목 이야기가 나오면 후보 3~5개와 각각의 이유·어감을 제안하되, 장·소설 제목을 직접 바꿨다고 말하지 않는다. 본문을 바꾸지 않는 기존 원칙은 그대로.

### 4. 고정 배치

- 챕터 목록(`nav`)과 오른쪽 `ClaudePanel` 래퍼에 `lg:sticky lg:top-4 lg:max-h-[calc(100dvh-2rem)] lg:overflow-y-auto`. 좁은 화면은 지금 그대로(위아래로 쌓임).

### 5. 문단 정리 모달 (검토 모드 전용)

- 툴바에 `문단 정리` 버튼. 네이티브 `<dialog>`(`showModal`)로 연다 — 포커스 가두기·Esc·배경 잠금이 기본 제공되어 의존성이 필요 없다. 이 모달로 기존 장별 패널(`StructureSuggestions`, `DialogueSplit`)을 대체하고 두 컴포넌트는 삭제한다(규칙·검증 로직은 `splitDialogue`, `suggestStructureAction`, `applyStructureChanges`를 그대로 재사용).
- 옵션: `대사 나누기` 체크(기본 켜짐) + 방식 `대사만 따로`(기본)/`서술 붙이기`; `Claude 문단 구성 제안` 체크(기본 켜짐) + 신경 쓸 점(선택).
- 실행 순서: (a) 현재 편집 중인 글에 대사 나누기를 전 장에 적용한 **작업본**을 만든다(즉시, 짝이 안 맞아 건너뛴 문단 번호 기록). (b) 체크했다면 작업본의 각 장에 대해 `suggestStructureAction`을 **1장부터 순서대로** 호출한다(진행 `3/10장`, `멈추기`). 한 장이 실패해도 나머지는 계속하고 실패한 장은 오류 줄로 남긴다. Claude가 나뉜 문단을 보고 제안하도록 (a)가 먼저다.
- 결과 화면: 장마다 한 줄(`N장 · 지금 a문단 → 대사 나누기 b문단 → 적용 시 c문단`)과 `이 장 적용` 체크(바뀐 장만 기본 켜짐), 펼치면 Claude 제안(나누기/합치기, 이유, 수락·거절)과 건너뛴 문단 안내. `모두 수락` 버튼. 맨 아래 `이 구성으로 전체 적용` / `적용하지 않고 닫기`.
- 적용: 체크된 장의 문단을 한 번에 교체하고(장 제목·확인 상태는 그대로), 첫 변경 장의 첫 문단을 선택한다. 기존 자동 저장·나란히 보기·`수정됨` 표시가 그대로 붙는다.
- 모달이 열린 동안 편집 화면은 잠겨 있으므로 별도의 "낡은 제안" 처리는 없다. 실행 중 모달을 닫으면 남은 호출을 중단한다.

## 결정한 것(사용자 외)

- 제목 길이 한도 120자, 대화 대상은 칩으로 명시 선택, 모달은 네이티브 `<dialog>`, Claude 호출은 장 순차(병렬 아님 — 속도 제한과 진행 표시를 위해), 한 장 실패 시 계속 진행.
- 같은 세션에서 소설 제목 입력 중 대화를 보내면 캐시된 본문 앞부분이 달라져 캐시 적중이 떨어질 수 있다(제목이 바뀐 직후 한 번). 감수.

## 빌더에게 남긴 것

- 입력·모달·칩의 정확한 마크업과 스타일(기존 패널 스타일을 따른다), `dialog` 닫힘/취소 이벤트 처리, 파일 분리(`lib/paragraphCleanup.ts`에 순수 로직, `components/admin/ParagraphCleanupModal.tsx`에 UI).
- 테스트: story-generator의 검증·병합·핸들러(`tests/masterReview.test.js`, `tests/adminHandlers.test.js`), 웹의 `masterReview`/`chatProtocol`/`chat`/`paragraphCleanup`/액션 단위 테스트. 컴포넌트 렌더 테스트 환경이 없어 화면은 수동 확인 목록으로 넘긴다.

## 알려 둘 한계

- 장마다 Claude를 한 번씩 부르므로 10장이면 호출 10번(시간·비용). 결과가 마음에 안 들면 다시 실행하는 값이 든다.
- 게시된 소설의 제목은 이번에도 바꿀 수 없다(게시 수정 함수는 문단 표현 전용).
