# 편집 대화: 읽는 범위 스위치 (문단 중심 / 전체 원고) (짧은 설계)

2026-11-22. 작은 변경. 대화창 구조는 `2026-11-21-editor-chat-and-download-design.md`, 직전 변경은 `2026-11-22-editor-chat-clear-and-edit-notice-design.md` 참고.

## 의도와 이유

한국어 마스터 원고가 A4 30장이 넘는다(한국어는 토큰이 많아 대략 4만~8만 토큰). 지금은 질문마다 원고 전체를 Claude에게 보낸다.
프롬프트 캐시(`buildChatMessages`의 `cache_control`)가 있지만, 편집 작업은 "문단을 고치고 → 질문 → 또 고치고 → 질문"으로 흘러서 문단을 고칠 때마다(그리고 5분 넘게 쉬면) 캐시가 깨져 전체를 다시 쓴다. 문장 다듬기 같은 국소적인 질문에는 낭비다.

## 목표 / 비목표

- 목표: 문단을 보고 있을 때 "이 문단 중심"으로 질문하면 설정 + 그 문단과 앞뒤 한 문단만 보내 입력을 줄인다. 편집자가 "전체 원고"로 바꿀 수 있다.
- 목표: 캐시 적중량을 서버 로그에 남겨 실제 효과를 확인할 수 있게 한다.
- 비목표: 이전 메시지를 고쳐 쓰기(캐시 안정성), 범위 자동 판단, 앞뒤 문단 수 설정, 제목 질문의 범위 축소.
- 안티골: 범위가 좁은 걸 숨겨서 Claude가 안 본 내용을 확신 있게 틀리게 답하는 것.

## 접근 (검토한 것과 선택)

1. 대상 버튼(문단/장 제목/소설 제목)과 묶기 — 문단을 고른 상태가 대부분이라 거의 모든 질문이 문단만 보게 되어 제외.
2. **범위를 따로 고르는 스위치 — 선택(편집자 선택: 기본값은 문단 중심).**
3. 로그만 먼저 — 편집자가 스위치를 먼저 진행하기로 해서 로그는 이 작업에 함께 넣는다.

## 설계

**범위의 뜻**
- `전체 원고`: 지금과 같다(`buildStoryContext` 전체).
- `이 문단 중심`: `[설정]`(제목, 레벨, 문체, 인물 말투) + `[소설 본문]` 아래에 그 장 제목과 지금 문단 및 앞뒤 한 문단(같은 장 안에서만). 문단 번호 `[n]`은 그대로 붙인다. `[소설 본문]` 바로 아래에 "(범위: N장 M문단과 앞뒤 한 문단만 보여 드립니다. 나머지 원고는 이 대화에 포함되지 않았습니다.)" 안내 줄을 둔다.
- 문단 중심은 **지금 보는 곳이 문단일 때만** 적용된다. 제목 대상(소설 제목·장 제목)과 전체 읽기 화면은 항상 전체 원고다(제목 후보는 이야기 전체가 필요).
- 문단을 찾을 수 없으면(장/문단 번호가 현재 원고에 없음) 전체 원고로 보낸다.

**요청 형식**
- 요청 본문에 선택 필드 `limitTo?: { chapterNumber: number; paragraphIndex: number }`을 추가한다. 있으면 서버가 문단 중심 본문을 만들고, 없으면 지금과 같다. `parseChatRequest`가 모양을 검증한다(정수, `chapterNumber ≥ 1`, `paragraphIndex ≥ 0`, 그 밖에는 거절).
- 클라이언트의 `chapters`는 지금처럼 전체를 보낸다(검증과 편집 중인 본문 전달용). 서버가 자르기만 한다.

**화면**
- 문단을 보고 있을 때(`chatFocus`가 문단) 대상 버튼 아래에 `읽는 범위` 두 버튼 `이 문단 중심 / 전체 원고`(`aria-pressed`). 기본값은 `이 문단 중심`. 상태는 `ClaudePanel`이 들고 있어 탭을 오가도 유지된다.
- 안내 문구(`focusSummary`): 문단 중심이면 "지금 보는 곳: N장 M문단 · 이 문단과 앞뒤만 읽고 있어요", 전체면 지금 문구 그대로.

**시스템 프롬프트(`buildChatSystemPrompt`) 한 줄**
- `[소설 본문]` 아래에 "(범위: …)" 안내가 있으면 일부만 본 것이다. 범위 밖(앞뒤 흐름, 다른 장의 설정·복선·말투)은 추측으로 단정하지 말고, 전체가 필요한 질문이면 대화창의 "전체 원고"를 눌러 다시 물어보라고 안내하라. 이전 대화에서 이미 본 내용은 참고해도 된다.

**캐시**
- 전체 원고 모드는 지금과 같다(본문 블록 캐시, 이전 메시지 재전송 모양 유지). 문단 중심 본문은 작아서 캐시 효과가 거의 없지만 `buildChatMessages`를 건드리지 않고 그대로 둔다(쓰기 비용이 작아 손해가 미미하다).
- 알림 줄·포커스 줄 등 이미 메시지에 박힌 값은 바꾸지 않는다.

**사용량 로그**
- `streamConversation`이 `finalMessage()`의 `usage`를 선택 콜백 `onUsage`로 넘기고, `streamChat`이 `console.info("[editor-chat] usage", { scope, input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens })`로 남긴다(토큰 수만, 본문·제목은 남기지 않는다).

## 테스트

- `lib/claude/editing.test.ts`: 문단 중심 본문(설정 포함, 앞뒤 한 문단만, 같은 장 안, 번호 유지, 범위 안내 줄, 첫/마지막 문단 경계, 없는 문단은 전체로 대체)과 시스템 프롬프트 새 문장.
- `lib/chatProtocol.test.ts`: 범위 → `limitTo` 변환 순수 함수(문단+문단 중심만 값, 전체 범위·제목·전체 읽기는 undefined).
- `lib/claude/chat.test.ts`: `parseChatRequest`의 `limitTo` 검증, `streamChat`이 `limitTo`로 문단 중심 본문을 쓰고 usage를 로그로 남김.
- `lib/claude/structured.test.ts`: `streamConversation`이 `onUsage`를 부른다.
- 컴포넌트 렌더링 테스트는 이 프로젝트에 없어 스위치와 안내 문구는 수동 확인.

- 앞뒤 한 문단, 같은 장 안에서만.

- 문단을 못 찾으면 전체로 보낸다.
