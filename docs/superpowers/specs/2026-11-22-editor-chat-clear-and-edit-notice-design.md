# 편집 대화: 대화 지우기 + 원고 수정 알림 (짧은 설계)

2026-11-22. 작은 변경(파일 5개 안팎). 대화창 구조는 `2026-11-21-editor-chat-and-download-design.md` 참고.

## 의도와 이유

편집자가 문단을 옮겨 다니거나 문단을 고친 뒤 대화로 돌아오면 두 가지가 불편하다.

1. 이전 문단과 나눈 맥락이 계속 섞여 따라온다. 지울 방법이 없다.
2. 문단을 고친 뒤 대화하면 Claude가 "제가 잘못된 정보를 드렸네요"처럼 반응한다.

**원인(코드로 확인):** 요청마다 *현재* 원고 전체(`buildStoryContext`, 매번 새로 만듦)와 *옛* 대화 기록(옛 답변이 인용한 옛 구절 포함)이 함께 간다. 원고가 대화 중에 바뀔 수 있다는 안내가 시스템 프롬프트(`buildChatSystemPrompt`)에 없어서, Claude는 옛 인용과 현재 원고의 불일치를 자기 오류로 해석한다.

## 목표 / 비목표

- 목표: (a) 대화를 비우는 버튼, (b) 원고가 바뀐 뒤의 첫 메시지에 그 사실을 Claude에게 확실히 알리기.
- 비목표: 어느 문단이 바뀌었는지 알려주기(문단 추가·이동으로 번호가 밀려 복잡함 — 필요해지면 별도 작업), 문단을 옮길 때 자동 초기화(대화창은 문단을 옮겨도 유지되도록 일부러 설계됨, 장 전체 논의가 사라짐), 대화 저장.
- 안티골: 옛 메시지 내용을 바꿔 프롬프트 캐시를 깨는 것(`withFocus` 주석 참고 — 보낼 때의 값을 메시지에 박아 두는 이유).

## 접근 (검토한 것과 선택)

1. 버튼만 — 원인이 그대로라 제외.
2. 버튼 + 프롬프트 한 줄 — Claude가 알아채길 기대만 함.
3. **버튼 + 변경 알림 + 프롬프트 한 줄 — 선택(편집자 선택).**
4. 문단 이동 시 자동 지우기 — 위 이유로 제외.

## 설계

**대화 지우기**
- `EditorChat`의 대화 영역 위쪽에 `대화 지우기` 버튼. 대화가 비어 있으면 비활성.
- 누르면: 대화가 있으면 `window.confirm`(게시본 `초안 버리기`와 같은 방식) → 진행 중인 응답을 멈추고 `turns`를 비운다. 저장하는 곳이 없으므로 되돌릴 수 없다.
- 입력창에 쓰던 글(`chatDraft`)과 고른 대상(문단/장 제목/소설 제목)은 그대로 둔다.
- `useEditorChat`에 `clear()` 추가. 응답 중에 지울 때를 위해: `clear`가 컨트롤러를 abort하고 `abortRef`를 즉시 비우며 `sending`을 끈다. `send`의 스트림 콜백·`finally`는 자기 컨트롤러가 아직 현재 것일 때만 `patchLast`/상태 초기화를 한다(안 그러면 늦게 온 이벤트가 빈 목록의 마지막 턴을 고치다 오류가 나거나, 지운 직후 새로 보낸 메시지가 `abortRef` 때문에 무시됨).
- 지우면 "마지막으로 보낸 원고 열쇠"도 비운다(비교할 옛 답변이 없음).

**원고 수정 알림**
- `useEditorChat`이 마지막 전송 시점의 열쇠를 ref로 들고 있는다. 열쇠 = `chaptersKey(chapters)` + 편집 중인 소설 제목(`context.title`).
- `send`에서 열쇠를 이전 값과 비교해, 이전 값이 있고 다르면 user 메시지 앞에 `[참고: 직전 질문 뒤에 원고가 수정됐어요]` 줄을 붙인다. 메시지 모양: `[지금 보는 곳: …]\n[참고: …]\n본문`. 보낼 때의 값을 메시지에 박아 두므로 이후 요청에서도 옛 메시지가 같은 모양으로 재전송된다(캐시 유지).
- `stripFocus`가 알림 줄도 함께 떼어 편집자 말풍선에는 보이지 않게 한다.
- `buildChatSystemPrompt` 대화 원칙에 한 줄 추가: 원고는 대화 중에 편집자가 고쳐 바뀔 수 있고 현재 원고가 기준이다. `[참고: …원고가 수정됐어요]`가 있으면 옛 답변이 인용한 구절이 지금 없는 건 편집자가 고친 것이지 답변의 오류가 아니다. 사과하거나 옛 답변을 틀렸다고 하지 말고 현재 원고 기준으로 이어서 답하라.

## 테스트

- `lib/chatProtocol.test.ts`: `stripFocus`가 알림 줄까지 뗀다(알림 없는 옛 형식도 그대로 동작).
- 알림 여부 판단(열쇠 비교)은 순수 함수로 빼서 단위 테스트: 첫 전송은 알림 없음, 같으면 없음, 다르면 있음, 제목만 바뀌어도 있음, 지운 뒤 첫 전송은 없음.
- `editing.ts` 프롬프트 테스트가 있으면 새 문장을 확인. (이 프로젝트엔 컴포넌트 렌더링 테스트가 없어 버튼과 응답 중 지우기는 수동 확인.)

## 빌더에게 맡기는 것

- 순수 함수의 이름·위치, 버튼의 정확한 위치·문구 다듬기.
- 열쇠 비교는 정규화한 문단 기준이라 저장 시 정규화만으로는 알림이 뜨지 않는다(`chaptersKey`의 기존 동작).

## 내가 정한 것(확인 필요)

- 지우기에는 확인 창을 띄운다(대화가 있을 때만).
- 지워도 입력 중인 글과 대상 선택은 남긴다.
